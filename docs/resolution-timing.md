# 処理順とチェックポイント（実装設計）
根拠 M pp.15–22。図の矢印で解決する規則と一般則を混同しない。

## 共通
primitive実行→勝敗／デッキ空の即時処理→その境界で許可された誘発効果解決→次ステップ。
通常誘発は現在の効果解決中に即実行せずpendingへ。置換・無効・リフレッシュは別機構。
推理／アクション／コンタクトはマニュアル手順図の項目間をcheckpointにする。
各checkpointでターン側pending優先、所有者が選択。1つ解決後に優先条件を再評価。

## 使用カードの位置
通常イベント: 手札→RESOLVING→解決→remove。
カットイン: 手札→remove→選択した効果解決。
ヒラメキ: 証拠→PENDING_EVIDENCE_REMOVAL→発動／辞退・解決→remove。
変装: 手札カードと現場の役割を交代し元カードをデッキ下。登場イベントを出さない。
RESOLVINGとPENDING_EVIDENCE_REMOVALは設計上の一時位置。公式の新エリアを意味しない。

## 中止条件
- ガードまで: アクション者／対象キャラ離脱で終了。
- コンタクト途中: どちらか離脱でAP比較省略→終了処理。
- ガードなし事件アクションの手順: 行動者離脱でも証拠獲得・終了まで続行。
- 勝敗確定: どの段階でも対戦終了。後続処理を実行しない。

## 再開可能な処理フレーム
frameId, handlerId, step, remainingCount, locals, returnFrameId。
リフレッシュ後に同じ処理を最初から再実行しない。実行済み移動と残数を保持。
処理スタックとpendingEffectsとpendingDecisionをsnapshotに保存。
再帰リフレッシュ等の複雑な相互作用はU04。未確認裁定を勝手に補完しない。
