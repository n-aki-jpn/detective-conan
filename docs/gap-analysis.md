## まとめと優先順位

1. **U08 運用基盤**（最も影響大）: 認証基盤は実装済みだが、**パスワード/PIN追加・レート制限・HTTPS** が未整備のままでは公開運用で不正アクセスのリスク。次に **DB移行（SQLite）** と **切断猶予・再接続** が複数人同時利用の前提条件。
2. **固定シードシミュレーション**: CPU強化学習の再現性確保に必須。設計は既に書かれており実装コストは比較的低い。
3. **CI/CD・ヘルスチェック**: 運用開始前に最小限の `cargo test` 自動実行と `/health` を導入したい。
4. **ルール裁定（U01/U04/U05）**: 競技運用・公式準拠を目指す際に解消が必要。
