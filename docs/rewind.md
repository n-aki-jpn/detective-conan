# 巻き戻し（Undo／リワインド）機能 設計

作成日: 2026-11-25
状態: 設計＋実装（バックエンド・テスト）

## 1. 目的

対戦中に「相手の合意があれば、直前の自分の1手だけを巻き戻せる」機能を提供する。
ミスタップ・効果の選択ミスなどを、双方合意の上で訂正できるようにするのが目的。

## 2. 方式：スナップショット復元

`MatchEngine` は `Clone`（内部RNG `StdRng` も `Clone`）であるため、
**意思決定（`submit_decision`）の直前にエンジン全体を `clone` して保持**し、
巻き戻し時にそのクローンでエンジンを丸ごと置き換える。

- 再シミュレーション方式と違い、決定論性・HashMap反復順のリスクに依存しない。
- `replay_log` もエンジンに属するため、復元するとリプレイログも時点まで巻き戻る（整合的）。

保持するスナップショットは「**直前の 1 手分のみ**」。

## 3. リーク防止（最重要）

名探偵コナンTCG は手札・伏せなど隠情報を持つ非完全情報ゲーム。
「攻撃 → 相手のガード成否／手札開示を見てから巻き戻す」を許すと、
巻き戻し側が不正に隠情報を得て有利になる。

### 許可条件（すべて満たすときのみ巻き戻し可）

1. 巻き戻し対象手が **要求者本人の打った手** である（他人の手は戻せない）。
2. その手の **直後から現在までの間、相手側（＝その手の打者以外）が
   まだ意思決定を提出していない**。
   - 相手の応答（ガード成否・ヒント開示・対象選択・誘発順序など）が
     一度でも盤面で解決されていれば、隠情報が開示されたことになり **巻き戻し不可**。
3. **双方の合意**（要求 → 相手側が同意）が成立している。

実装上、条件2は「スナップショット採番時にカウンタを 0 にリセットし、
以後 打者以外が `submit_decision` するたびに +1、カウンタが 0 の間のみ可」として追跡する。

### 巻き戻し対象となる「自分の手」

- `mainAction`（メイン行動：キャラ登場・事件進行など）
- `hintPlay`（ヒント使用）

`guard` / `cutin` / `targetSelect` / `deckSearch` / `modeSelect` / `triggerOrder`
などの「応答系」は巻き戻し対象にしない（応答は情報開示に直結するため）。

## 4. 合意フロー

```
要求者P1: POST /api/rewind            → rewind_request = {requester: P1}
                                   （canRewind 判定 true なら待受状態に）
相手  P2: POST /api/rewind/accept     → 条件再検証 → 成功ならエンジン復元
          （または POST /api/rewind/reject で拒否）
```

- CPU対戦では、人間側の要求に対し CPU は自動で同意する（`p2_is_cpu` のとき accept 相当を自動実行）。
- 同意・拒否・実行時に `rewind` イベントをリプレイログへ記録する。

## 5. 状態（MatchRoom に追加）

| フィールド | 意味 |
|---|---|
| `snapshot: Option<MatchEngine>` | 直前の「自分の手」提出直前のエンジン |
| `snapshot_actor: Option<String>` | その手を打ったプレイヤーID |
| `snapshot_kind: Option<String>` | その decision の kind |
| `others_decided_since_snapshot: usize` | 採番後に打者以外が提出した回数（0なら巻き戻し可） |
| `rewind_request: Option<String>` | 巻き戻し要求中の要求者ID（None=要求なし） |

## 6. API

| メソッド | パス | 説明 |
|---|---|---|
| POST | `/api/rewind` | 巻き戻しを要求。`{roomId, playerId}`。可否を返す |
| POST | `/api/rewind/accept` | 相手側が同意し実行。`{roomId, playerId}` |
| POST | `/api/rewind/reject` | 相手側が拒否。`{roomId, playerId}` |

`GET /api/state` の観測に `rewind`（`{available, requestedBy, canAccept}`）を追加し、
フロントはこれを見てボタンを出す。

## 7. 既知の制約

- 巻き戻しは 1 手単位・直前の 1 手のみ（多段戻しは不可）。
- 同一エンジンコードバージョンでのみ整合（エンジン変更で過去スナップショット互換は保証外）。
- 合意制のため、CPU戦以外は相手の操作が必要。
